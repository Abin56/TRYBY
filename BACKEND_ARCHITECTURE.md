## 3. Auth.js Architecture

### Strategy: JWT sessions (edge-compatible)

```
Request
  ↓
middleware.ts  ←─ auth() checks JWT cookie
  ↓
Route Handler  ←─ auth() for per-request session
  ↓
lib/auth.ts    ←─ NextAuth config
  ↓
PrismaAdapter  ←─ Account / Session / VerificationToken tables
```

### Providers
| Provider    | Use case                          |
|-------------|-----------------------------------|
| Google      | Social login (primary)            |
| Credentials | Email+OTP (phone login, future)   |

### JWT payload
```ts
{ id: string, role: UserRole, email: string, name: string }
```

### Route protection matrix
| Path prefix        | Rule                              |
|--------------------|-----------------------------------|
| `/account/**`      | Must be logged in                 |
| `/checkout/**`     | Must be logged in                 |
| `/orders/**`       | Must be logged in                 |
| `/wishlist/**`     | Must be logged in                 |
| `/supplier/**`     | role === SUPPLIER or ADMIN        |
| `/admin/**`        | role === ADMIN                    |
| Everything else    | Public                            |

## 4. Migration Plan

### Phase 1 — Initial setup (run once)
```bash
# 1. Install dependencies
npm install prisma @prisma/client @auth/prisma-adapter next-auth zod razorpay

# 2. Set environment variables in .env
DATABASE_URL="postgresql://user:pass@localhost:5432/tryby_sports"
NEXTAUTH_SECRET="<random-256-bit>"
NEXTAUTH_URL="http://localhost:3000"
GOOGLE_CLIENT_ID="..."
GOOGLE_CLIENT_SECRET="..."
RAZORPAY_KEY_ID="rzp_test_..."
RAZORPAY_KEY_SECRET="..."

# 3. Generate first migration
npx prisma migrate dev --name init

# 4. Generate Prisma Client
npx prisma generate
```

### Phase 2 — Seed data
```bash
# Create prisma/seed.ts with:
#   - 6 categories (one per sport)
#   - Sample products with variants + images + badges
#   - Announcement bar messages
#   - Test coupons (WELCOME10, TRYBY15)
npx prisma db seed
```

### Phase 3 — Production deployment (Vercel + Neon/Supabase)
```bash
# Set DATABASE_URL to connection pooler URL (port 6543 on Neon)
# Add ?pgbouncer=true&connection_limit=1 to DATABASE_URL
npx prisma migrate deploy   # runs all pending migrations
```

### Phase 4 — Weekly sold count reset (cron)
```
# Add a Vercel cron job or pg_cron:
# Every Monday 00:00 IST — reset weeklySoldCount to 0 on all products
UPDATE "Product" SET "weeklySoldCount" = 0;
```

## 5. Key Design Decisions

| Decision | Rationale |
|---|---|
| JWT sessions (not DB sessions) | Edge-compatible, no DB hit on every request |
| `weeklySoldCount` on Product | Avoids expensive ORDER aggregation for "sold this week" display |
| `avgRating` + `reviewCount` denormalized | Avoids expensive AVG query on product list pages |
| Soft sport filter via `Sport` enum | Enables fast index scans; category tree still available for deeper hierarchy |
| Order items snapshot `productName`, `variantSku` | Protects order history when products change |
| `BundleItem` table | Enables "Complete Your Kit" upsell without complex product relationships |
| HMAC verify on Razorpay webhook | Prevents replay attacks; signature verified before any DB write |
| `AnnouncementMessage` in DB | Marketing can update announcements without code deployments |
