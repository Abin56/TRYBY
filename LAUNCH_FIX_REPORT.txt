[FIXED] Content Security Policy (CSP) header added
  Problem : No CSP header — XSS attack surface was entirely open
  Solution: Full CSP with separate directives for:
              script-src: self + Razorpay checkout + Sentry CDN
              style-src:  self + unsafe-inline + fonts.googleapis.com
              font-src:   self + fonts.gstatic.com
              img-src:    self + data + blob + Cloudinary + Unsplash
              connect-src: self + Razorpay API + Sentry ingest
              frame-src:  Razorpay (iframe for payment)
              object-src: none (blocks Flash/plugins)
            Also added Strict-Transport-Security (HSTS) header
  Files changed:
    • store/next.config.ts — CSP_DIRECTIVES constant + header config

[FIXED] INTERNAL_API_SECRET now mandatory in production
  Problem : All 5 internal routes had `if (!secret) return true` — any
            unauthenticated caller could invoke them if the env var was
            unset in production (which it was, since it wasn't in .env.local)
  Solution: Created shared guardInternalRoute() helper in lib/internal-auth.ts
              - In production without secret → 500 (deployment misconfiguration)
              - In development without secret → allowed (dev convenience)
              - With secret set → validates x-internal-secret header → 403 if mismatch
            Patched all 4 affected internal routes to use the shared guard
  Files changed:
